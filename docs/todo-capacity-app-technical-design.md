# Todo 容量管理 App 技术方案

## 1. 目标与产品原则

本产品帮助个人面对有限的每日精力时做出真实的承诺。任务像气球，未完成后会变得更显眼、需要重新评估；每日计划像烧杯，用户可承接的容量有限。系统的目标是促成安排、拆分、暂缓或删除的决定，而不是制造逾期债务或惩罚用户。

### 设计原则

1. **先收集，后承诺**：新想法进入收件箱，不自动占用今天的容量。
2. **每日有上限**：计划日容量由用户设置，应用以容量点呈现剩余空间。
3. **未完成需重新决策**：日终未完成任务进入复盘，不自动滚动到明天。
4. **任务可缩小**：允许拆成更小的下一步，避免大而模糊的事项长期堆积。
5. **复盘不带惩罚**：膨胀仅表达需要关注和重新判断，不增加任务的客观工作量或容量占用。
6. **容量可校准**：后续可参考计划容量和实际完成量，建议调整默认容量；MVP 不自动修改用户设置。

## 2. 用户与使用场景

首个版本面向希望管理个人日常工作、学习和生活事项的单用户。典型场景：

- 想到一件事时快速记下，但不想立刻塞进今天。
- 早晨从收件箱挑选任务，安排到今天并控制总容量。
- 完成任务后看到容量释放。
- 当天结束时处理未完成事项，明确安排、拆小、暂缓或删除。
- 查看未来某天是否已经超出自己的容量。

## 3. 信息架构与页面

产品以 H5 和手机 App 为目标，采用移动端优先的单列布局。主导航固定在底部，包含四个一级页面：**今日、收件箱、复盘、计划**。H5 与 App 共用页面结构；较宽屏幕只增加留白并限制内容最大宽度，不切换为桌面侧边栏。新增任务入口在各页保持可达。

### 3.1 今日

- 顶部显示日期和紧凑的容量摘要（已用、剩余或超额）；点摘要可查看容量明细。
- 页面主体是待办气球容器，每件待办显示为一只气球，气球标题展示任务名。
- 气球大小表示任务未完成周期数对应的关注级别，不表示工作量，不改变容量统计。每只气球对应一个圆形刚体，在容器中受重力和碰撞影响自然移动、堆叠与静止；球体之间不得重叠，碰到侧壁或底部时球面贴合内沿。
- 点气球打开任务详情页/底部面板，可编辑、查看容量估算和选择后续动作；完成必须由用户明确确认。
- 今日为空时引导从收件箱安排任务；容量已满时提示用户先完成、移出或缩小其他任务。
- 完成确认后，气球播放缩小再淡出的反馈，随后从容器移除；任务记录完成时间，原计划日期的未完成容量释放。
- 新增任务入口固定在底部导航上方，保证单手可触达。

### 3.2 收件箱

- 展示尚未安排日期的待办。
- 支持快速新增、编辑、删除、估算容量、设为今天或安排到其他日期。
- 收件箱任务不计入任何一天的容量。
- 按创建时间展示，支持搜索/筛选属于后续增强项。

### 3.3 复盘

- 展示已到期且未完成、等待用户决定的任务，并显示当前气球尺寸/未完成周期数。
- 每个任务提供四个明确决策：
  - **重新安排**：选择日期，按目标日期剩余容量提示是否超额。
  - **拆小**：创建一个或多个子任务；原任务可标记为已拆分/归档，避免父子重复占用。
  - **暂缓**：移入以后清单，不占近期日期容量。
  - **删除**：确认后软删除，保留撤销能力。
- 提供“稍后处理”入口；未决事项保持在复盘列表，不自动安排。
- 首次复盘用简短说明解释这是重新选择，不是失败记录。

### 3.4 计划

- 默认显示本周日期横向条，选中日期后以单列方式查看当天气球和容量摘要。
- 可查看、添加和调整选中日期的任务。
- 超额日期突出显示使用量与上限，提供移出、重排、拆分操作。
- MVP 可先实现周视图，月视图、拖拽跨日排程列为后续增强。

### 3.5 移动端原型交互规范

- 页面从上到下依次为：安全区与页面标题、日期/容量摘要、可滚动的气球容器、浮动新增按钮、底部四项导航。底部操作避开 iOS/Android 安全区。
- 气球容器使用 Matter.js 2D 刚体模拟。球体以少量随机横向差异进入容器，在重力、摩擦和碰撞作用下落下并稳定；球与球、球与侧壁/底部均以圆形边界求解，不额外插入行间距或容器内边距。容器宽度变化时重建边界并保留球体相对位置；容器高度随球数增加，页面可纵向滚动。物理世界只在容器挂载且有球时运行，静止球允许休眠。
- 容器为顶部开放的竖直槽，左右墙和底部是静态刚体。物理边界与可见容器内沿共用内容区坐标，球的渲染直径与物理碰撞直径一致；如果可用宽度小于单球直径，球体按容器宽度等比缩小至可容纳尺寸。两球直径之和大于容器宽度时自然上下错位堆叠，不做横向压扁或重叠。
- 球体内显示任务名和负载信息，避免球底部贴住容器时把标题挤到容器外。标题超长时单行截断，完整内容由详情面板提供；球体本身可点击，保持键盘焦点提示。
- 气球级别 `level = min(carryoverCount, 4)`，直径按级别为 56、70、84、98、112 CSS px。0 级为新安排任务；级别每增加 1，尺寸增加 14 px；4 级及以上保持最大尺寸。气球至少保留 44×44 CSS px 触控区域。
- 点气球进入任务详情底部面板，显示任务名、容量、已跨未完成周期数，以及「标记完成」「安排日期」「拆小」「暂缓」「删除」操作。
- 点「标记完成」后，在任务详情面板内出现明确的二次确认控件「确认完成」。确认成功后先写入已完成状态，再将气球缩小至基准尺寸并淡出（总时长约 300 ms）；动画结束后从活动容器移除，并显示可撤销提示。取消确认不改变数据。
- 复盘页复用相同任务详情和动作面板；完成任务保留同一确认与动画语义。计划页以本周日期横条切换日期，避免手机上使用密集月历网格。
- H5 与手机 App 复用以上信息层级、状态和触控流程；宽屏内容区最大宽度为 480 px 并居中，底部导航仍对应四个页面。

## 4. 核心业务流程

### 新建与安排

`快速记录 → 收件箱 → 估算容量 → 选择日期 → 校验容量 → 安排`

若容量未知，任务可先进入收件箱；安排到日期时要求估算或选择默认值。若目标日期超额，允许用户显式确认安排，但要清楚显示超额并给出取舍入口，避免静默超载。

### 完成

`查看任务 → 点击“标记完成” → 明确确认 → 写入 completed → 气球缩小并淡出`

确认动作成功后记录 `completedAt`，并从原计划日期的未完成容量统计中释放。动画只呈现已提交的状态变化，不承担数据写入职责。完成状态可以撤销；撤销后若原日期已过，任务回到复盘队列。

### 日终与复盘

周期定义为用户设置时区中的一个本地自然日；MVP 日界线为本地午夜（`dayBoundaryHour = 0`）。计划任务跨过其计划日仍未完成时，在首次进入应用/今日页时幂等转为 `review`，并将 `carryoverCount` 增加 1。用户明确选择重新安排、拆小、暂缓或删除后，状态按决策更新。重新安排后的任务保留当前气球级别；只有它再次跨过一个计划日未完成时才增加一级。暂缓任务离开计划期间不累计周期数，之后重新安排时保留已有级别。

## 5. 容量规则

### MVP 计量单位

采用 **容量点**，由用户给任务估算点数。MVP 提供易理解的默认档位，例如轻量 `1`、普通 `2`、较重 `3`，并允许调整。每日容量是用户可配置的点数上限。界面可辅以分钟估算，但内部运算统一使用整数容量点，避免混合单位。

### 统计口径

- `plannedLoad(date) = sum(task.load)`，仅统计该日期、状态为 `planned` 且未完成的任务。
- `remaining(date) = dailyCapacity - plannedLoad(date)`。
- `overflow(date) = max(0, plannedLoad(date) - dailyCapacity)`。
- 完成、暂缓、删除、移出日期的任务不计入计划负载。
- 分拆父任务后，父任务不再计入负载；仅子任务参与统计。
- 已完成的任务从当前负载中释放，但历史计划/完成记录仍保留用于统计。

### 气球/关注级别

气球视觉级别由 `carryoverCount` 决定，采用有上限的五档：0 次为 56 px；1、2、3、4 次分别为 70、84、98、112 px；4 次及以上保持最大尺寸。尺寸同时用于 DOM 绘制和 Matter.js 圆形碰撞体。初始横向位置随机；气球之间不设人为间距，由碰撞求解器阻止重叠。侧壁和底部的碰撞边界贴合容器可见内沿；如果总直径大于宽度，气球自然错位堆叠。容器高度随球数增加并允许页面纵向滚动，页面不保存物理坐标，重新进入时重新落球。级别只影响球体显示和复盘排序，不改变任务负载、优先级或日期。暂缓期间不增加计数。完成时先缩至基准尺寸再淡出并移出活动容器。

### 容量初始化与校准

- 初次设置由用户选择偏保守的每日容量，可随时在设置中调整。
- MVP 提供最近 14 天的计划/完成容量摘要，但不据此自动更改上限。
- 后续可在用户明确同意后建议新容量，并解释推荐依据。

## 6. 状态与数据模型

首版采用本地优先的单用户模型；领域模型与存储实现隔离，方便后续接入账号同步。

### Task

```ts
type TaskStatus = 'inbox' | 'planned' | 'review' | 'someday' | 'completed' | 'archived'

interface Task {
  id: string
  title: string
  notes?: string
  status: TaskStatus
  load: number | null            // 正整数容量点；收件箱内可为空
  plannedDate: string | null     // 本地日历日期 YYYY-MM-DD
  priority: 'low' | 'normal' | 'high'
  parentId: string | null
  carryoverCount: number           // 已计入的未完成计划日数；映射为最多五档气球尺寸
  lastProcessedCycleDate: string | null // 最近计入 carryoverCount 的计划日期键，避免重复处理
  createdAt: string              // ISO timestamp
  updatedAt: string
  completedAt: string | null
  deletedAt: string | null       // 软删除
  sortOrder: number
}
```

### UserPreferences

```ts
interface UserPreferences {
  dailyCapacity: number
  capacityUnit: 'points'
  timezone: string               // IANA 时区
  dayBoundaryHour: number        // MVP 固定为 0（本地午夜）；自定义日界线属于后续增强
  weekStartsOn: 0 | 1            // 0 周日，1 周一
}
```

### TaskDecision（复盘审计记录）

```ts
interface TaskDecision {
  id: string
  taskId: string
  action: 'missed_cycle' | 'reschedule' | 'split' | 'someday' | 'delete' | 'complete' | 'undo'
  fromDate: string | null
  toDate: string | null
  createdAt: string
  metadata?: Record<string, unknown>
}
```

容量设置变更记录、完整分析事件可后续再加。MVP 至少保留决策时间和改期次数，以支持复盘和撤销。

## 7. 技术架构

### 现状与建议

仓库当前包含 React 18、Wasp、Musae UI 组件库和 Tauri 2；现有页面可以整体替换。尚未发现 Wasp 应用定义、数据库 schema 或同步服务配置。因此建议：

- 页面继续使用 React 与现有 UI 依赖；重构路由和应用壳层。
- 先实现本地单用户体验，桌面端可利用 Tauri；Web 端使用浏览器持久化。
- 通过 `TaskRepository` 抽象存储接口，按运行环境选择本地适配器：普通浏览器 H5 使用 IndexedDB；Tauri 桌面/移动 App 使用 SQLite，由 Rust 命令封装数据库访问和事务。业务组件不直接读写浏览器或原生数据库 API。
- 若后续确定需要多设备登录同步，再启用/完善 Wasp 服务端与数据库层，并增加同步冲突处理；不在 MVP 默认引入账户、云端 API 或订阅。
- 对日期处理采用本地时区日期键，不直接用 UTC 日期截断来判断“今天”。
- 气球视觉由 Matter.js `0.20.x` 驱动；使用 JavaScript 2D 引擎，不新增 WebAssembly 依赖。组件只把刚体位置同步到 DOM 样式，不在每个物理步触发 React 重渲染。

### 气球物理容器

- 每个任务气球对应一个圆形动态刚体，半径为展示直径的一半。初始化时在容器内随机选择不重叠的落点，并给予很小的横向速度；重力负责下落，摩擦和低恢复系数使球体自然停稳。
- 左右侧壁与底部使用 Matter.js 静态矩形刚体。边界内沿与容器 `clientWidth`/物理高度一致，壁体向容器外延伸，避免碰撞边界本身给球体留出可见空隙。容器顶部开放，不设天花板。
- Matter.js 引擎启用休眠；每帧最多补算 2 个固定步长（`1000 / 60 ms`），全部球休眠后停止帧循环。页面切到后台造成的长间隔会被限制，避免恢复时球体突然弹飞。组件卸载时取消 `requestAnimationFrame` 并清理引擎。
- 容器高度按气球数量、最大直径和当前宽度估算，至少为 240 CSS px。宽度或任务尺寸变化时重建物理世界；已有球的位置按宽度比例保留，新球从随机空位生成。位置只存在内存中，刷新或重新进入页面后重新初始化。
- DOM 气球的可见圆形直径必须等于物理刚体直径；标题和负载作为球内覆盖文字显示，不参与碰撞。点按圆体仍打开任务详情；完成动画期间保留该刚体，动画结束随任务状态从活动列表移除。

### 分层

```text
src/
  app/                 # 路由、导航、全局布局
  pages/               # Today, Inbox, Review, Planner, Settings
  features/
    tasks/             # 任务表单、任务列表、状态操作
    capacity/          # 烧杯展示、负载计算、超载提示
    review/            # 复盘队列和决策动作
    planner/           # 周视图和日期安排
  domain/
    task.ts            # 状态、实体和领域规则
    capacity.ts        # 负载/剩余/超额纯函数
    review.ts          # 日切与未完成任务转换
    task-actions.ts    # 复盘、完成、撤销等领域动作
  data/
    task-repository.ts # 持久化接口
    indexeddb/         # 普通浏览器适配器
    tauri-sqlite/      # Tauri 桌面/移动端适配器
  shared/              # 通用 UI、日期和格式化
src-tauri/src/
  commands.rs          # SQLite 命令：状态提交在 Rust/SQLite 事务中执行
src-tauri/migrations/
  001_initial.sql      # SQLite schema 初始化
```

UI 只调用领域用例，不自行计算负载。容量计算、任务迁移、拆分规则采用纯函数/服务，方便后续测试和跨 Web/Tauri 复用。

### 持久化与备份

- 普通浏览器 H5 使用 IndexedDB；Tauri 桌面/移动 App 使用 SQLite 文件数据库，由 Rust `rusqlite` 命令处理读写。两端采用相同的领域实体、状态机和 repository 接口，但各自拥有适配底层存储的数据映射与 schema 迁移。
- IndexedDB 操作异步，适合浏览器端保存结构化对象、索引和较多历史任务；SQLite 适合 Tauri 端的结构化查询、事务和数据迁移。两端均为本地优先，当前不做云同步。
- Tauri 前端只通过 `@tauri-apps/api/core` 的 `invoke` 调用受控命令；Rust 命令使用 SQLite 事务将任务状态变更与 `TaskDecision` 一起提交。事务边界留在 Rust 侧，避免跨多次异步前端请求拼接事务。
- 启动时检查各自 schema 版本并执行迁移；任务变更经 repository 写入，避免页面直接访问存储层。
- JSON 导出/导入定义为跨平台备份格式，与 IndexedDB object store 和 SQLite 表结构解耦；导入前校验版本、字段和重复 ID。
- 桌面/App 端切换安装版本或数据库 schema 时保留原始数据库备份；浏览器端需提供导出功能，避免用户清理站点数据时丢失任务。
- 所有任务变更更新 `updatedAt`；软删除支持撤销。
- MVP 提供 JSON 导出/导入作为基础备份和迁移手段，导入前预览并校验版本、重复 ID 与字段。
- 多端同步、账号体系、实时协同不纳入 MVP。

## 8. 关键交互与边界处理

- **目标日期已超额**：给出剩余/超出点数，并允许用户显式继续；安排完成后容量条进入超额状态。
- **没有容量估算**：收件箱允许保存；安排到某天前要求选档位或自定义点数。
- **日期跨时区变化**：使用用户当前 IANA 时区生成本地日期键；时区变更不批量改写历史日期。
- **午夜前后任务切换**：日界线按偏好处理；MVP 默认本地午夜。
- **周期计数与日切**：在进入今日页/应用恢复前调用一次 `processMissedTasks(todayLocalDate)`。查询 `status = planned AND plannedDate < todayLocalDate` 的任务；对每项任务在同一 repository 事务内确认 `lastProcessedCycleDate !== plannedDate`，将状态设为 `review`、`carryoverCount += 1`、`lastProcessedCycleDate = plannedDate`，并写入 `missed_cycle` 决策记录。状态更新与审计记录原子提交；重复调用不重复计数。该任务只处理其已安排的计划日，不对应用未打开期间的每个自然日补计数，因为任务未被自动滚入那些日期。
- **复盘动作**：`review` 任务在用户决策前保持 review。重新安排时写入新 `plannedDate` 并回到 planned，保留 carryoverCount；暂缓转为 someday，离开计划期间不计数；拆小按父子容量规则执行；完成只由明确确认操作触发。
- **完成动画与提交顺序**：先持久化 `completed`、`completedAt` 并更新容量视图，再播放缩小淡出动画。动画取消、页面关闭或刷新均不回滚状态；撤销通过单独的 undo 动作处理。
- **气球视觉映射**：`level = min(carryoverCount, 4)`，直径 `56 + 14 × level` CSS px；视觉上限 112 px。该映射只属于 UI 表现，不参与领域容量运算。
- **拆分任务**：要求至少建立一个子任务；父任务不再计容量，避免重复占用。
- **删除误操作**：软删除并提供撤销提示。
- **重复点击/离线写入**：本地 repository 操作按任务 ID 幂等更新；IndexedDB 事务保护父子拆分和状态转换。
- **空状态/初次体验**：示例说明容量点概念，允许跳过引导并以后设置。

## 10. 验收标准

- 用户可以快速记录任务并留在收件箱，不强制立即排期。
- 今日页显示每日上限、已用容量、剩余容量，完成任务后数字正确释放。
- 超额安排前后均能清楚看到超额量，系统不会静默挤掉已有任务。
- 未完成计划任务进入复盘，关闭/刷新应用后仍保持待决状态。
- 用户可对复盘任务重新安排、拆小、暂缓或删除；操作后状态和容量统计一致。
- 重复改期只增加关注级别，不会自动增加容量点。
- 一个未完成计划日只使气球膨胀一级；日切用例重复运行不重复计数。
- 暂缓任务离开计划期间不增加未完成周期数；重新安排时保留原有气球级别。
- 确认完成后先持久化完成状态，再播放缩小淡出；动画中断或刷新不改变完成状态。
- 气球大小不改变容量统计；Matter.js 容器中球体不会相互穿透，侧壁和底部碰撞边界贴合可见内沿；球径和大于容器宽度时自然错位堆叠，标题信息留在球体内部。
- H5 与手机 App 使用相同的移动端页面结构和状态行为；宽屏不切换成侧边栏。
- 父任务拆分后不与子任务重复计入容量。
- 本地日期统计遵循配置时区；跨午夜/时区变化不会把任务错误归入前一天。
- 导出数据可重新导入，非法或不兼容数据有明确错误，不覆盖现有数据。

## 11. 关键产品决策记录

| 决策 | MVP 选择 | 理由 |
|---|---|---|
| 任务容量单位 | 整数容量点 | 易懂且避免把主界面变成工时表 |
| 新任务默认去向 | 收件箱 | 捕获与承诺分开，减少今天计划膨胀 |
| 未完成处理 | 进入复盘、人工决策 | 避免无声滚动导致任务债务 |
| 膨胀机制 | 每个未完成计划日增加一级；`carryoverCount` 映射为最多五档气球尺寸 | 保留气球隐喻，不增加惩罚性工作量或容量 |
| 周期定义 | 用户时区的本地自然日，MVP 本地午夜切日 | 与每日计划和日终复盘一致 |
| 完成反馈 | 用户明确二次确认后持久化完成，再播放气球缩小淡出 | 让完成由用户决定，并使视觉反馈与状态一致 |
| 主平台布局 | H5/手机 App 移动端单列与底部导航 | 符合手机触控并复用交互 |
| 超容量安排 | 允许显式确认 | 现实中容量可被用户主动突破，但不能隐瞒代价 |
| 存储 | 浏览器 H5 使用 IndexedDB；Tauri App 使用 SQLite | 两者适合各自运行环境，并由 repository 接口隔离底层差异 |
| Tauri SQLite 事务边界 | Rust 命令通过 `rusqlite` 执行读写事务 | SQL 插件 JS API 没有事务方法；避免用多次异步请求拼接事务（[API 参考](https://v2.tauri.app/zh-cn/reference/javascript/sql/)，[事务支持讨论](https://github.com/tauri-apps/plugins-workspace/issues/886)） |
| 跨设备同步 | 后续阶段 | 避免在产品规则未验证前增加后端复杂度 |
