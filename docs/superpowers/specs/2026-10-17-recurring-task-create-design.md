# 周期待办创建页设计

## 目标

将底部导航中间的“添加”入口改为独立的新建页。用户为一个长期存在的待办填写标题、明细、周期和开始日期。周期内待办每天出现在今日页；未完成时，每跨过一个周期，待办的气球变大。系统始终沿用同一条待办记录，不生成副本。完成或删除后，待办不再出现在活动视图；完成记录继续保留。

## 页面与入口

- 添加入口导航到独立新建页；页面提供返回入口并保留底部导航。
- 页面字段：标题、明细、周期数值及单位（天/周/月）、开始日期。
- 标题必填；周期是正整数，默认每 1 天；开始日期默认用户时区的今天。
- 开始日期是第一个周期的锚点。保存成功后返回今日页。
- 今日、收件箱、计划页中的快捷添加入口统一导航至新建页，避免绕过周期字段。
- 表单校验或保存失败时留在新建页并显示错误；取消返回上一页。

## 周期与待办生命周期

- 周期由 `interval`（正整数）和 `unit`（day、week、month）表示。
- 周按 7 个日历日计算。月按开始日期的日号锚定；目标月份没有该日时取月末。例如从 1 月 31 日开始按月计算，边界依次为 2 月末、3 月 31 日。
- 日期使用用户时区的本地日历日期键计算，不通过固定小时数推算日/月边界，避免夏令时偏差。
- 待办从开始日期起每天出现在今日页，直到完成或删除。每次跨过周期边界仍未完成时，同一记录的 `carryoverCount` 增加 1，周期推进，气球按现有档位规则变大。
- 应用离线跨过多个周期时，补记所有已跨过的周期。推进操作必须幂等，重复启动或刷新不得重复计数；每个边界写入唯一 `missed_cycle` 决策。
- 完成待办保留在存储中并从活动视图移除；软删除沿用现有行为。
- 没有周期字段的既有待办保持原有单日计划和复盘逻辑，不自动转换为周期待办。

## 今日视图与容量

- 周期待办在开始日期之后的每个当前日期均显示在今日气球容器中。
- 活动周期待办按其现有容量值计入每日容量摘要；默认容量值沿用现有新建待办默认值。
- 气球直径继续由 `carryoverCount` 决定，不影响容量计算。
- 已完成、已删除以及尚未到开始日期的待办不计入今日活动项或容量。

## 数据与存储

- 在 `Task` 上增加可选周期信息，包含正整数间隔和单位；保留开始日期及最近处理的周期边界，支撑离线补记和幂等推进。
- 新建周期待办使用现有 `planned` 活动状态。既有无周期字段的 JSON 任务继续按旧流程运行。
- 浏览器端通过现有 IndexedDB repository 保存对象；Tauri 端通过现有 SQLite repository 保存 JSON payload。两者使用相同日期规则并保持决策记录一致。
- SQLite 存储整个任务 payload；IndexedDB 对象允许增加字段，因此不需要破坏性迁移。旧记录的缺省周期表示一次性待办。
- 周期日期算法应保持 TypeScript 与 Rust 日切处理一致；每次补记的任务和决策在对应存储的原子边界内提交。

## 验收方式

- 新建页可以填写标题、明细、天/周/月周期和默认今天的开始日期，且校验与保存错误清楚可见。
- 四个添加入口均进入同一新建页；保存后返回今日页。
- 未到开始日期的周期任务不显示；开始日期当天及之后每天显示。
- 周期边界未完成会将同一待办的未完成计数加一、气球增大并进入下一周期，不创建额外任务。
- 离线跨越多个边界时各边界只计一次；连续多次启动不重复计数。
- 月末规则和用户时区边界一致；旧待办仍按原有单日复盘规则工作。
- 完成或删除后从活动视图移除，记录仍按现有保留/软删除规则存储。
